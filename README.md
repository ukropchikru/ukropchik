# Укропчик — сервис о здоровом питании

Сайт на HTML5, CSS3 и JavaScript без сборки и фреймворков. Работает в России без VPN (см. ниже).
База данных и авторизация: [Supabase](https://supabase.com) (PostgreSQL), хостинг — любой статический: Netlify, Vercel или GitHub Pages.

## Что внутри

| Страница | Что делает |
|---|---|
| `index.html` | Главная: быстрый расчёт ИМТ, «О нас», правильное питание, замены продуктов, услуги, контакты |
| `calculator.html` | Калькулятор ИМТ и калорий (формула Миффлина — Сан Жеора), БЖУ, норма и трекер воды, рекомендации; сравнение вредных продуктов и альтернатив с графиками |
| `diet.html` | Конструктор рациона на день и неделю: автоподбор меню под норму, БЖУ, график по дням, печать, сохранение в аккаунт |
| `forum.html` | Форум: темы, разделы, поиск, ответы |
| `login.html` | Вход, регистрация, выбор плана, восстановление пароля |
| `recipes.html` | Рецепты с КБЖУ, фильтрами (завтраки, вегетарианское, без глютена, без лактозы, быстро) и кнопками «в рацион» / «в дневник» |
| `diary.html` | Дневник питания: записи по дням, сравнение с нормой калорий и БЖУ, график за 7 дней, перенос меню из конструктора |
| `shopping.html` | Список покупок из рациона на день или неделю (готовые блюда пересчитаны в продукты) |
| `scanner.html` | Сканер штрихкодов камерой телефона: состав, Nutri-Score, «светофор» сахара/соли/жиров, полезная замена, запись в дневник |
| `account.html` | Личный кабинет: дневник веса с графиком, история расчётов, тема оформления, напоминания пить воду, установка приложения |

Дополнительно: тёмная тема (кнопка 🌙 в шапке или как в системе) и PWA — сайт можно установить на телефон как приложение, он открывается и без интернета.

```
css/style.css        стили и адаптив под телефоны
js/config.js         ключи Supabase (заполнить)
js/db.js             работа с базой (Supabase или демо-режим)
js/data.js           продукты, замены, категории ИМТ
js/main.js           шапка, подвал, меню, уведомления
js/recipes-data.js   рецепты
js/plan.js           общие функции рациона
js/theme.js          тема оформления (подключается первым)
js/*.js              логика отдельных страниц
sw.js                service worker: офлайн-режим и уведомления
manifest.webmanifest описание приложения для установки на телефон
supabase/schema.sql             таблицы: профили, рационы, форум, сообщения
supabase/schema-2-personal.sql  таблицы: вес, история расчётов, дневник питания
```

Пока в `js/config.js` нет ключей, сайт работает в **демо-режиме**: регистрация, рационы и форум сохраняются только в браузере. Вверху страниц показывается жёлтая плашка.

## Запуск на компьютере

Откройте папку в VS Code и запустите расширение **Live Server**, либо в терминале:

```bash
python -m http.server 8000
```

и откройте http://localhost:8000

## Шаг 1. Подключить базу данных (Supabase)

1. Зарегистрируйтесь на https://supabase.com → **New project** (бесплатный план). Запомните пароль базы.
2. Откройте **SQL Editor** → **New query**, вставьте всё содержимое `supabase/schema.sql` и нажмите **Run**. Затем так же выполните `supabase/schema-2-personal.sql`.
3. Откройте **Project Settings → API** и скопируйте в `js/config.js`:
   - `Project URL` → `SUPABASE_URL`
   - `anon public` key → `SUPABASE_ANON_KEY`
4. **Authentication → Sign In / Providers → Email**:
   - оставьте **Confirm email** включённым, если хотите подтверждение почты письмом;
   - или выключите, чтобы входить сразу после регистрации (удобно для защиты проекта).
5. После публикации сайта (шаг 2) откройте **Authentication → URL Configuration** и укажите адрес сайта в **Site URL** и **Redirect URLs** — иначе ссылки из писем (подтверждение, сброс пароля) будут вести на localhost.

Ключ `anon` публичный, его нормально хранить в коде сайта. Доступ к данным ограничивают правила RLS из `schema.sql`: пользователь видит только свои рационы, писать на форуме можно только после входа, сообщения из формы контактов читаются только в панели Supabase (**Table Editor → contact_messages**).

Дневник питания, вес и история расчётов работают и без входа — тогда они хранятся в браузере. После входа они сохраняются в базе и доступны с любого устройства.

## Шаг 2. Выложить в интернет

### Вариант А — Netlify (самый простой)

1. Зайдите на https://app.netlify.com/drop
2. Перетащите папку `site` в окно браузера.
3. Через несколько секунд сайт будет доступен по адресу вида `https://имя.netlify.app`. Название можно поменять в **Site configuration → Change site name**.

Чтобы обновить сайт, перетащите папку снова в разделе **Deploys**.

### Вариант Б — GitHub Pages

1. Создайте репозиторий на GitHub и загрузите в него содержимое папки `site` (файл `index.html` должен лежать в корне).
2. **Settings → Pages → Source: Deploy from a branch**, ветка `main`, папка `/ (root)`.
3. Сайт появится по адресу `https://ваш-логин.github.io/имя-репозитория/`.

### Свой домен

Купите домен (например, `ukropchik.ru` у reg.ru или nic.ru) и привяжите его в настройках Netlify (**Domain management**) или GitHub Pages (**Custom domain**). HTTPS-сертификат выдаётся бесплатно автоматически.

## Приложение (PWA) и обновления

- После публикации на https сайт можно установить: в Chrome на Android — кнопка «Установить» внизу экрана или в кабинете; на iPhone — Safari → «Поделиться» → «На экран „Домой“».
- Сайт кэшируется для работы без интернета. **После изменения файлов увеличьте версию в `sw.js`** (`ukropchik-v1` → `ukropchik-v2`), иначе часть пользователей увидит старую версию.
- Сканер штрихкодов требует https (на Netlify и GitHub Pages он есть) и разрешения на камеру. Данные о продуктах берутся из открытой базы Open Food Facts.
- Напоминания о воде приходят, пока сайт или приложение открыто (в том числе в фоне). Для уведомлений при полностью закрытом приложении нужен push-сервер — это можно добавить позже через Supabase Edge Functions.

## Размещение на своём хостинге (Beget, Timeweb, REG.RU)

Нужен хостинг с PHP и SSL. Загрузите **содержимое** папки (не саму папку) в корень сайта, обычно это `public_html` или `ваш-домен/public_html`.
Файлы `.htaccess` и `proxy.php` обязательны: они включают https и пересылают запросы к базе через ваш домен.
После переезда укажите новый адрес в Supabase: Authentication → URL Configuration (Site URL и Redirect URLs).

## Работа в России без VPN

Домены Supabase и некоторых CDN в России блокируются. Поэтому опубликованный сайт ни к чему не обращается напрямую:
- запросы к базе идут через ваш домен Netlify: `/sb/...` → Supabase (правило в файле `_redirects`);
- запросы сканера — через `/off/...` → Open Food Facts;
- библиотеки (`js/vendor/`) и шрифт (`fonts/`) лежат в папке сайта.

Файл `_redirects` обязательно должен лежать в корне папки, которую вы загружаете в Netlify. На localhost прокси нет, там запросы идут напрямую (может понадобиться VPN).
Если вы создадите новый проект Supabase, поменяйте его адрес и в `js/config.js`, и в `_redirects`.

## Перед запуском для реальных пользователей

- Заполните ИНН и ОГРН в подвале (`js/main.js`, функция `renderFooter`) и ссылки на VK и Telegram.
- Добавьте страницу политики обработки персональных данных — сайт собирает почту и имя (152-ФЗ).
- Для коммерческого запуска в РФ учтите требование хранить персональные данные россиян на серверах в России (242-ФЗ): Supabase размещается за рубежом. Для учебного проекта это не критично; для продакшена можно перейти на российский хостинг базы (например, Yandex Cloud или Selectel).
- Замените фото в `img/` на исходники в хорошем качестве (сейчас они вырезаны из макета).
